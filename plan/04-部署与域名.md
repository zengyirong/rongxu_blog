# 04 · 部署与域名

配套总方案：[个人静态技术博客方案 V1.0](./个人静态技术博客方案%20V1.0.md) · [01-落地执行清单](./01-落地执行清单.md)

账号侧（GitHub / Cloudflare / 域名注册商）需你本人操作；本文给出仓库侧约定与控制台配置清单。

---

## 整体流程

```text
写文章 / 改站点
    ↓
git commit & push → GitHub（main）
    ↓
Cloudflare Pages 检测 push
    ↓
pnpm install → pnpm docs:build
    ↓
发布 docs/.vitepress/dist
    ↓
CDN + HTTPS → *.pages.dev 或 YOUR_DOMAIN
```

---

## 一、GitHub 仓库

1. 创建仓库（公有或私有均可；Pages 均支持）
2. 本地关联并推送：

```bash
git init
git add .
git commit -m "chore: init vitepress blog"
git branch -M main
git remote add origin https://github.com/YOUR_GITHUB/YOUR_REPO.git
git push -u origin main
```

3. 约定：`main` = 生产环境；功能改动可用 `feature/*`，依赖 Pages Preview。

根 `README.md` 应包含：环境要求、`pnpm docs:dev` / `docs:build`、指向 `plan/` 文档。

---

## 二、Cloudflare Pages

### 创建项目

1. Cloudflare Dashboard → Workers & Pages → Create → Pages
2. Connect to Git → 授权并选择博客仓库
3. 配置构建：

| 配置项                 | 值                            |
| ---------------------- | ----------------------------- |
| Production branch      | `main`                        |
| Framework preset       | 可选 None / VitePress（若有） |
| Build command          | `pnpm docs:build`             |
| Build output directory | `docs/.vitepress/dist`        |
| Root directory         | `/`（仓库根）                 |

### 环境与包管理

- 建议在 Pages 设置中指定 Node 兼容 **22+**
- 使用 pnpm：仓库含 `pnpm-lock.yaml` 时，Pages 一般会自动选用 pnpm；若未识别，可在环境变量或构建配置中声明（以 Cloudflare 当前文档为准）
- Install command 默认可为 `pnpm install`（若控制台可填）

### 首次发布

构建成功后会得到：

```text
https://<project>.pages.dev
```

先用该地址验收，再绑自定义域名。

### Preview

非 Production 分支的 push 可生成预览 URL，适合改主题 / 导航时先看效果再合并 `main`。

---

## 三、构建命令核对（本地先验）

上线前在本地确认：

```bash
pnpm install
pnpm docs:build
```

检查：

- 退出码为 0
- 存在 `docs/.vitepress/dist/index.html`
- 存在 `sitemap.xml`（若已配置 `sitemap.hostname`）

与 Pages 上的 Build command / Output directory **必须一致**。

---

## 四、自定义域名

### 阶段策略

1. **先跑通**：只用 `*.pages.dev`
2. **内容稳定后**：购买域名并绑定

### 绑定步骤（概要）

1. 域名 DNS 交由 Cloudflare（Nameserver 指向 CF）
2. Pages 项目 → Custom domains → 添加 `YOUR_DOMAIN` 或 `www.YOUR_DOMAIN`
3. 按提示添加 CNAME / apex 记录（Pages 控制台通常会引导）
4. 等待证书签发，用 `https://YOUR_DOMAIN` 访问

### 配置回写

域名生效后更新仓库：

- `docs/.vitepress/config.ts` 中 `sitemap.hostname` → `https://YOUR_DOMAIN`
- 若有 canonical / OG url，一并改为正式域名
- 再 push 触发一次构建

## 五、Cloudflare Web Analytics

V1 统计推荐用 Cloudflare Web Analytics，不必自建 PV/UV。

可选方式：

- Pages 项目 Metrics / Web Analytics 中开启（以当前控制台为准）
- 或创建 Web Analytics 站点并按说明嵌入（静态站通常有 beacon 脚本；若走 CF 托管集成，优先用官方一键方案）

不需要：

- 自建统计表
- 自写统计 API

## 六、部署验收清单

- [ ] `main` push 后 Pages 构建成功
- [ ] `*.pages.dev` 首页、文章、关于、项目可打开
- [ ] 深色模式、本地搜索可用
- [ ] HTTPS 正常（Pages 默认提供）
- [ ]（可选）Preview 分支可访问
- [ ]（可选）自定义域名与 sitemap 主机名一致
- [ ]（可选）Web Analytics 有访问数据

## 七、常见问题

| 现象             | 排查                                                            |
| ---------------- | --------------------------------------------------------------- |
| 构建找不到 pnpm  | 确认有 `pnpm-lock.yaml`；检查 Node 版本；显式 install 命令      |
| 404 静态资源     | 确认 output 为 `docs/.vitepress/dist`；图片是否在 `docs/public` |
| 样式 / 路由异常  | 本地 `pnpm docs:preview` 对比；检查 `base` 是否误设             |
| sitemap 域名错误 | 改 `hostname` 后重新部署                                        |

| 占位符        | 含义          |
